# Skreed pre-launch site: rules for Claude Code

This repo is the skreed.in pre-launch teaser (live until 14 November 2026, then skreed.in redirects to skreed.com at the launch, 15 November 2026 00:00 IST). Read `docs/00-IDEATION.md` for the plan and `docs/data/shades-240.json` for the shade system before touching UI.

## Brand facts (from the 2026-27 catalog, `docs/brand/`)
- 240 shades, exactly 24 per family. Families in catalog order, by their site names (singular, Sam 2026-10-14): Frosty White, Blissful Blue, Playful Pink, Vivid Violet, Mellow Yellow, Basic Brown, Blushing Coral, Stormy Grey, Go Green, Roaring Red (ids `frosty-white` ... `basic-brown` ... `roaring-red`). The 2026-27 catalog prints the plural names (Frosty Whites, Earthy Browns), kept as `catalogName` in `shades-240.json` and never shown on the site. Use the display names in `shades-240.json` (e.g. "Sky", not "Sky Blue").
- Tagline: "Tech Essentials That Go Beyond Basic." Line: "colour is personal."
- Finishes: Matte and Gloss. Case types: Snap, Tough, MagTough, Armor, Ultra (plus Sylvr metallic).
- Voice: confident, minimal, design-led, short sentences. Never discount language. No hype.
- Visual identity: Pearl Whisper (#F7F6F3) pages alternating with Urban Slate (#383F43), Ember Luxe (#FF9900) as the single accent for the primary button and focus rings, circle swatches in a 6x4 grid, soft lifestyle photography on neutral backdrops. Extend this. Do not invent a new look.
- Typography (`docs/brand/type-system.md`, decided 2026-10-05): three families, four self-hosted files, 98 KB. **Poppins 700** is the voice: headlines in sentence case, the manifesto, the quiz question, the enlarged tile name, "You are #212", the 404. **Source Serif 4** 400 and 600, roman only, is the letter: hero sub-line, standfirsts, founders' note, day-in-shades stories, confirmation sentence. **Open Sans** 400 to 600 is the fittings: labels, inputs, buttons, family names, every live numeral with tabular figures, eyebrow, footer, legal prose. Never all-caps headlines, never italic, never a live number in Poppins.
- Voice (brand guide): first person, short sentences, active voice, sensory colour words. "We believe in the power of color."

## graphify

The repository carries a knowledge graph of its own code and specs at `graphify-out/` (installed 2026-10-29; runbook `docs/research/11-graphify.md`). It is git-ignored: `npm run graph` builds it with no LLM (40 to 60 s clean, 11 s when nothing changed, a few minutes after a large spec edit), from every `.ts`, `.mjs`, `.astro`, `.py`, `.sh` and config `.json` file and from the heading structure, links and code-span mentions of every Markdown file. `prototypes/`, test fixtures, media and data files stay out by `.graphifyignore`.

The `/graphify` skill is `.claude/skills/graphify/SKILL.md` (with its `references/`); when the user types `/graphify`, follow it before anything else.

Rules:
- Before the first grep, search or source-file read for a question about the codebase, ask the graph: `graphify query "<question>"` for the scoped subgraph, `graphify explain "<file or symbol>"` for one thing and its connections, `graphify path "<A>" "<B>"` for how two things join (`--undirected` when the direction does not matter) and `graphify affected "<symbol>"` for what depends on it. Put this rule in every subagent prompt that explores code. Read raw files only for the lines the graph or an earlier read has located.
- Read `graphify-out/GRAPH_REPORT.md` only for a broad architecture review, or when query, path and explain do not surface enough.
- After changing code or specs, run `graphify update .` (`npm run graph`) so the graph stays current; the ship loop does this inside the build skill and again after the commit on PASS. Run it after a `git pull` or a branch switch too. `npm run graph:force` after a refactor that deletes code.
- If `graphify-out/graph.json` is missing (a fresh checkout or worktree), build it first. It is never committed; each checkout and each machine builds its own.
- Off until asked for, because each costs tokens or time: the semantic pass over the docs (`/graphify . --update`, subagents reading every spec for concept nodes), LLM names for the communities (`graphify label .`), and the PreToolUse hooks that nudge every search and read towards the graph (1.4 to 2.3 s per tool call on the Windows machine; section 8 of the runbook turns them on per machine).
