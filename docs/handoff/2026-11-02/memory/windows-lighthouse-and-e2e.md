On the Windows machine (since 2026-10-28) Lighthouse runs from `node_modules/lighthouse/cli/index.js` with `CHROME_PATH` pointing at Playwright's headless shell (`C:/Users/skree/AppData/Local/ms-playwright/chromium_headless_shell-1194/chrome-win/headless_shell.exe`, installed by `npx playwright install chromium`) and `--chrome-flags="--headless --no-sandbox --disable-gpu --disable-dev-shm-usage"`, against the production build served by `npx wrangler dev --ip 127.0.0.1 --port 8790 --assets ./dist`. It only works once the machine is quiet: with stale `wrangler`, `workerd`, Lighthouse and Chrome processes of other sessions alive (29 Chrome processes, 2.4 GB free) every attempt crashed or hung (`chrome-launcher` silent for ten minutes, `Inspector.targetCrashed`, `NO_NAVSTART`, `TARGET_CRASHED`). A set taken while a Playwright suite or a frames render runs is noise (TBT up to 1.1 s on the same bytes), so take the three runs with nothing else running. Its JSON goes in the scratchpad: Playwright wipes `test-results/` on every run. The e2e suites run against a wrangler on 8787 serving a test build written to its own folder (`astro build --outDir dist-s5t` with the test flags, then `node scripts/csp.mjs --dist dist-s5t`) with `CHROME_PATH="C:/Program Files/Google/Chrome/Application/chrome.exe" BASE_URL="http://127.0.0.1:8787/" SKREED_DIST=dist-s5t npx playwright test <specs> --project e2e --workers 1`; a page-level suite (`tiers.spec.ts`'s picture count) breaks when a section adds pictures, so run `a11y-breakpoints`, `csp`, `tiers`, `island`, `to-top` and `locked-values` for every new section, not only the section's own spec. The quiz-gate ride rows in `quiz.spec.ts` ("QG AC3 and AC4 Skip quiz on the intro", "QG AC4 what ends the ride", "QG AC4 and AC5 on ?tier=hero3d") fail here by frame timing on the untouched default branch too (checked 2026-10-29 against a base build in a scratch worktree: samples a frame off the ride's curve, a landing 20 ms early), so a failure of those rows is attributed to the machine unless the ride's code changed; `-g "AC4"` catches them, so grep the quiz's own rows by name.

`python3` is not on this machine (2026-11-02: only `python`, without Pillow or numpy), so every e2e row that measures pixels through `tests/harness/pixels.py` fails before it measures, on any branch: `countdown.spec.ts` AC4.6 (390, 1280 and at zero) and `cue-logotype.spec.ts` AC5.3's two-tone focus ring over the poster. Attribute those to the machine. Put the spec paths before `--project e2e`, or write `--project=e2e`: `--project e2e <specs>` reads the paths as project names.

**Why:** The Lighthouse score for section 5 took an hour of crashed runs before the stale processes were found, and a second set was wasted by running it beside the quiz suite.

**How to apply:** Before Lighthouse, list `chrome.exe`, `node.exe` and `workerd.exe` with their command lines and end the stale ones (never another session's live run), wait for background suites to finish, then run the three. Related: [[windows-3d-review-with-playwright-chrome]].

Seen 2026-11-02: workerd (`wrangler dev`) cannot run from a worktree, or serve assets, under the session scratchpad's long path (Windows' 260-character limit): it dies with SQLITE_CANTOPEN, or prints "Ready on" and then answers nothing. Copy the build to a short folder such as `C:/Users/skree/AppData/Local/Temp/<short>` and run wrangler from a normal worktree with `--assets <short> --persist-to <short2>`. Ending the processes whose command line names the port misses workerd, which carries the port only inside `--socket-addr`: end the process that owns the listening port (`Get-NetTCPConnection -LocalPort <port>`). The quiz's laptop cases timed to 0.9 s ("Pictures, a mouse at 1280 x 800", "Pictures, the keyboard", "Pictures on a slow network (question 1 ...)") fail here by frame timing on the untouched default branch too (71678ed: 4 of 6 runs, alternated with a fix's 2 of 6), so attribute them to the machine unless the picture code changed; the quiz's phone cases are stable.

Also seen 2026-11-02 (the section index): in one session `--persist-to` a short folder (a worktree's own git-ignored `.wrangler/state`) was enough for a wrangler run from a scratchpad worktree serving its `./dist`; it served the whole afternoon and picked up rebuilds of `dist` without a restart. The e2e specs also run straight against an Astro dev server (hooks on, so `?tier=`, `?room=open` and `?intro=0` work): `BASE_URL=http://127.0.0.1:<dev port>/ SKREED_SKIP_BUILD_ID=1` (the build-identity setup otherwise compares the served page with `dist`); the first navigation can abort with ERR_ABORTED while Vite optimizes dependencies, so re-run that row once. 3D rows there need `?tier=hero3d` and the intro hook (`room.spec.ts` `open3d`): the harness forces SwiftShader, which the gate otherwise sends to the poster.
