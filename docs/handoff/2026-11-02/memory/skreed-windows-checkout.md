Machine facts the repo only partly records:
- Line endings are settled in the repo since merge 8f196e3 (2026-10-23): a root .gitattributes with `* text=auto eol=lf`, so a fresh clone needs no setting. The main clone also carries a redundant local core.autocrlf=false. Git for Windows' system config still has autocrlf on.
- npm on Windows runs scripts through cmd.exe, so the VAR=value prefixes in package.json fail. Run scripts with: npm --script-shell="C:\Program Files\Git\usr\bin\bash.exe" run <script>. Recorded in docs/HANDOFF.md section 3.
- Commit identity (Sam, 2026-10-23: "Sam Kamalesan only, same author, same email of the account"): repo-local user.name kamalesansam, user.email sam.kamalesan_2027@woxsen.edu.in, the same as his 216 earlier commits. Commit messages still end with the attribution line the session is given, as his hand-off rule says.
- A push to GitHub over HTTPS worked with no prompt on 2026-10-23 (Git Credential Manager); no entry shows in cmdkey, so the credential lives in GCM's own store.
- test:unit reports 193 tests at the default branch tip of 2026-10-29 (192 pass, 1 skipped: room-flux.test.ts's ffprobe probe, because ffprobe is not on the PATH here; not a fault); test:family reports 64. Other sessions add tests, so the counts move; the skip is the one constant.
- Stopping a background `npx wrangler dev` task through the harness kills only its shell: wrangler's node process and its workerd child stay up, keep the port and hold `.wrangler` inside the worktree, so `git worktree remove` fails with "Invalid argument" and leaves the folder behind. Find the workerd by the port in its command line (Get-CimInstance Win32_Process), stop it and its node parent by PID, then delete the folder and `git worktree prune`. Another agent session serves on 8791 from the same repo: never stop that one.
- Playwright's own Chromium is not installed (no ms-playwright cache), but Chrome is at C:Program FilesGoogleChromeApplicationchrome.exe and tests/harness/browser.ts honours CHROME_PATH, so the repo's e2e specs and frame scripts run here: CHROME_PATH="C:/Program Files/Google/Chrome/Application/chrome.exe" BASE_URL=http://127.0.0.1:<port>/ npx playwright test -c tests/family/playwright.config.ts <spec>. The harness forces SwiftShader, so a 3D family page costs 8 to 10 s per test and the landing's hero more; rows with tight timing (a fade read 100 ms after its duration, an 80 ms wait on the scroll handler, a per-frame count jump of 5) fail from frame gaps, not product faults (first run 2026-10-26: 33 of 40 back.spec.ts rows passed). The browser pane cannot take full frames while the session is not open in a window: hidden, it captures 800 x 600.
- For tests in a worktree, a node_modules junction to the main clone's install works; remove it with [System.IO.Directory]::Delete (never rm -rf, which would follow it) before git worktree remove. Not for a dev server or a build: Vite's dependency cache (node_modules/.vite) and Astro's data store would then live in the main clone's node_modules, shared with other sessions' servers. Give such a worktree its own `npm ci --prefer-offline --no-audit --no-fund` (2 min 20 s on 2026-11-02 with the npm cache warm).

**Why:** Sam's hand-off and migration prompt assume a Mac; these quirks cost a round of failing tests before they were found.

**How to apply:** use the bash script shell for every npm run, serve a build for review with `npx wrangler dev --ip 127.0.0.1 --port 8790`, never `npm run dev`, and keep Sam's process: own branch in a worktree, merge --no-ff, push, no PR. The main branch is checked out in the Documents clone, so a worktree session merges its branch there: `git -C C:/Users/skree/Documents/skreed-pre-launch merge --no-ff -F <msg> <branch>` after `git merge-tree --write-tree HEAD <branch>` in that clone exits 0 (no conflicts) and its status is clean; other sessions commit to main minutes apart (2026-10-29: the tip moved twice during one merge's checks), so check the tip right before and chain the check and the merge in one command. Done this way on 2026-10-29 for the graphify branch (b9d42a8). See [[skreed-sam-rules]].

Seen 2026-11-02: on Windows `chrome.exe --version` does not print a version; it hands off to the user's running Chrome and may open a window there. Read the version with `(Get-Item 'C:\Program Files\Google\Chrome\Application\chrome.exe').VersionInfo.ProductVersion`. In the Bash tool here a heredoc collapses a doubled backslash to one, and a long heredoc full of quotes and backticks can fail to parse: write such files (exact-replacement pairs, test code with `\'`) with the Write tool and apply them with a node script.
