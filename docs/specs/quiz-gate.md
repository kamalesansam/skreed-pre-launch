## 1. Goal

A visitor who reaches the quiz takes it or presses "Skip quiz", and only then does the page go on into section 4: the result opens section 4 below it, a press on Skip quiz opens it and carries the page down through the third wipe into the hall in 1.2 s, and either way it stays open for the rest of the visit. It serves goal 3 first (people share their details: every visitor now meets the quiz, which leads to the gift form) and goal 1 second (the quiz is the door into Skreed's world), from the goal stack in `docs/00-IDEATION.md` (lines 11 to 15).

## 9. Decisions taken

- **D1 The lock.** `section#room` is rendered with the `hidden` attribute and `data-locked` (Room.astro line 27) on every tier, so the document ends at the quiz and nothing scrolls past it. Without JavaScript the section shows, by `html:not(.js) .room[data-locked] { display: block; }` in room.css (an author rule outranks the browser's own `[hidden]` rule), because the quiz cannot run there and its no-JS line already sends the visitor to the families (quiz.md line 269). **`hidden` alone, not a class.** The browser's own `display: none` takes the section out of the layout, the accessibility tree, the Tab order and find-in-page at once, and both IntersectionObservers that watch it (its loader's, Room.astro line 113, and the hero's stage observer, hero.ts line 289) see it as not intersecting; room.css sets no `display` on `.room` itself (lines 11 to 18), so nothing fights it but the one no-JS rule. A class would need its own `display: none`, and `inert` or `aria-hidden` besides, to do the same. `data-locked` says why the section is hidden: it is what the scripts and the no-JS rule read, so a `hidden` set later for another reason is never taken for the lock. **The premise corrected.** The hero's `docTop` (hero.ts line 228) is `getBoundingClientRect().top + scrollY`, and a `display: none` element's rect is all zeros, so a hidden `#room` gives the current `scrollY`, a finite number, not NaN. Left so, the glue's section 4 span would be built round wherever the page stands (`top - one` to `top + one`, line 237), and a visitor's run stopping anywhere outside the other two spans would be settled to an end of it, up to a screen away. So `docTop` returns NaN for an element with no box (`getClientRects().length` is 0), and line 237's filter drops the span as it already does for a missing element. The same trap is in the director's layout read (director.ts line 169: a hidden section reads as `{ top: scrollY, height: 1 }`), which D5 guards.
