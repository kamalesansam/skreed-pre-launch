## Capture process

1. Capture. Paste the prompt in [CHROME-PROMPT.md](CHROME-PROMPT.md) into a claude.ai chat with the Chrome extension attached, one URL per run, with one or two sentences on what Sam liked and where it is. It returns a "Reference brief" in a fixed shape: page in one paragraph, sections top to bottom, the liked thing in detail with timings and easing, how it is built, fonts, colours, weight, assets, what makes it work, one-line recommendation. The brief is saved verbatim as `raw/<date>-<site>.brief.txt`. Nothing in it is edited.
2. Analysis. In the Claude Code session the brief is read against CLAUDE.md, docs/02-THE-SITE-IN-WORDS.md, docs/00-IDEATION.md sections 2 and 7, and research/10 sections 7 to 9, and refuted once. Every take must say how it is built without WebGL, what the phone and the laptop each get, what assets it needs and who owns them, how many days it costs and which rule it touches. Every drop must say why and cite the rule.
3. Reconciliation. When more than one site was captured on the same day, the per-site takes are merged into one list, the fixes from each refuter applied, and the merged list is what the per-site files report. The per-site file notes where its own analysis differed.
4. This folder. One file per reference, this README as the index, and the plan amendments below applied to docs/00, docs/01 and docs/02 in a separate edit pass. Specs in docs/specs cite the reference file, not the raw brief.
